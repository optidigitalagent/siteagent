# Decisions

- Telegram bot does not generate sites directly; it only accepts URL and writes a pending job.
- Codex command `go` owns execution, QA, publishing, and final Telegram notification.
- Queue defaults to local file and supports optional Git sync for Railway handoff.
- Railway deployment uses Dockerfile to guarantee Playwright Chromium dependencies.
- Website quality gates remain strict: score >= 88, no critical/high issues, technical pass, visual/business approval.
- Cloudflare Pages Direct Upload is the default production hosting provider for local Codex.
- Railway stays bot/inbox-only and receives no Cloudflare credentials.
- Local preview is allowed only with `HOSTING_PROVIDER=local` and `PUBLISH_REQUIRED=false`.
- The old Git publisher remains an explicit deprecated provider; it is never an implicit fallback.
- Wrangler credentials are passed only through the subprocess environment and Wrangler is pinned to major version 4.
- `SITE_BUILDER=codex_studio` is the default for new jobs. It invokes the repository-owned
  `$siteagent-web-studio` workflow and never silently falls back to `legacy_template`/Jinja.
- `.agents/skills` is the sole creative-skill source of truth. `plugins/siteagent-web-studio`
  is an optional IDE distribution mirror verified by checksums.
- Studio composition is generated by Codex first and then inspected; legacy `PageComposition`
  remains an audit/compatibility artifact, not a Studio rendering input.
- `CREATIVE_STUDIO_HUMAN_CALIBRATION_REQUIRED=true` blocks production publishing after creative
  acceptance until a human reviews real local fixture screenshots.
- Studio readiness is a pre-generation contract: full sites require an exact sourced product,
  confirmed language, at least three distinct sourced content themes, and five to eight
  deduplicated usable media assets. Sparse identified evidence is micro-site only; otherwise
  generation is blocked.
